# 🔑 Conceito-chave: git x migrações (por que um redeploy não bastava)

> Registrado em 2026-10-19. Este é o conceito que explica por que o
> `404` em `/superadmin` e o `"Migracao multi-tenant nao aplicada"`
> apareciam em produção mesmo com o código correto.

## As duas frases

1. **Código vai pelo git → o Dokploy rebuilda a imagem.**
   Foi por isso que o `404` apareceu em `/superadmin`: a página ainda **não
   estava no git**. Depois do push + redeploy, o arquivo passa a existir
   dentro da imagem e a rota responde.

2. **Migrações rodam no banco, não no código.**
   O `initdb.d` do docker-compose **só executa em volume novo**. O volume da
   VPS **já existe** → as tabelas `super_admins` / `tenants` / `tenant_users`
   nunca foram criadas. Por isso o login do super admin falhava mesmo com a
   aplicação no ar.

## A consequência

`git push` + redeploy no Dokploy resolve **a tela**, mas **não** cria tabelas.
Os dois problemas têm causas diferentes:

| Sintoma | Causa | Resolve com |
|---|---|---|
| `404` em `/superadmin` | arquivo/página ausente na imagem | git + rebuild |
| `"Migracao multi-tenant nao aplicada"` no login | tabelas ausentes no banco | migração no banco |

## Como isso deixou de ser um passo manual

Para o redeploy bastar (que é o comportamento esperado), o app passou a
**aplicar as migrações sozinho no boot**:

- `server/database/autoMigrate.js` roda a cada boot;
- lê todos os `.sql` de `server/database/migrations/` em ordem;
- é **idempotente** e controlado pela tabela `schema_migrations`;
- entende `DELIMITER` (necessário por causa das *procedures* das migrações);
- **nunca derruba o app**: erro é logado e a aplicação continua.

Desligar (se necessário): `AUTO_MIGRATE=0` no ambiente.

> As migrações ficam em `server/database/migrations/` (e não em `database/`)
> justamente para serem **copiadas para dentro da imagem** — o build context
> do Docker é `./server`.

## Regra prática

1. Alterou **código** → commit + push → redeploy no Dokploy.
2. Alterou **schema** → crie um novo `.sql` em `server/database/migrations/`
   → commit + push → redeploy (o app aplica no boot).
3. Em emergência/ambiente sem o app, aplique manualmente:
   `docs/02.DEPLOY_HOSTINGER_KVM4.md` → "Migração Multi-Tenant no Deploy".
